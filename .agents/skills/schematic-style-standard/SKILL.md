# 回路図スタイル：V3系標準（検証中）

**目的**：今回のA-2 V0→V3-polishと2026-11-22の回路レビューで得た作図ノウハウを一般化する。**USB-UART専用の座標や部品番号を他設計へ強制しない。**

共通の安全・差分保全・検証には`$schematic-design`も使う。`$pcb-pipeline`の上流コピーは触らない。

## 使用と優先順位

1. 電気的接続を保護し、間違った関係を図面上で描かない。
2. `HARD`：線分重複や誤接続に見える重なりを残さず、シンボル・文字を判読可能にする。
3. `STYLE`：パスコン縦向き、PWR_FLAG上向き、短いGND、実線の局所接続などを基本にする。
4. `PREFERENCE`：ICへの近接、配線総延長の抑制、ペア配線交差の最小化、ブロックのコンパクトさ。
5. 例外は箇所・理由・比較画像とともに記録し、人間が判断できるようにする。

配線やコンデンサを近づけるために既存の優先度の高い作図規約を黙って破ってはならない。**レビューで承認された表現（UARTの明確な非接続クロスなど）を無条件に消さない。**

## 作図方針の概要

- **機能配置**：USB→信号処理→外部IO、入力電源→二次電源といった流れを視覚化。単一シートで読める規模なら1枚で構成し、規模が大きければ階層シートを検討する。
- **接続**：局所の帰還・RC・保護・フィルタ・デカップリングを実線で追えるようにする。離れたブロック間は適切なネットラベルやバスを使う。省略する接続のラベルは原則として短い引出し線の端点に置く。
- **GND**：近接ピンを短くまとめ、可能な限り部品の下側近くに下向き三角のGND記号を置く。長距離のGND線で図面を横断させない。
- **電源**：電源名が判読できる統一の記号で示す。V3系では円を水平線が貫通する形を採用。PWR_FLAGはERC用途であり、電源表示記号と混同しない。
- **PWR_FLAG**：**描画方向は原則上向きに統一**。GND記号と誤認しない。KiCad標準PWR_FLAGの上向きは今回の環境では0°。CADやシンボル定義ごとに図柄を確認する。
- **コンデンサ**：電源/GNDのシャント（パスコン等）は**縦向き、上を電源、下をGND**。原則として電源側→分岐点→ICピンを視覚化し、GND線も短くする。**ICへの近接よりコンデンサの向き・Reference/Valueの可読性を優先**。
- **ESD部品**：信号線への枝とGND帰路を短く描き、保護される線の近くに置く。PCB上の配置制約を図面長さで代用しない。
- **フェライトビーズ**：標準インダクタに近いコイル図形を原則使用し、FBの識別、定数、型番、フットプリントと端子ネットを保持する。
- **ペア信号**：USB D+/D−のような差動信号は可能な限り並走させ、**不必要な交差の回数を減らす**。XTAL_IN/OUTも関連信号として近接するが、USBと同じ電気的差動配線条件とは扱わない。
- **配線幾何**：意味なく線を伸ばしたり折り返さない。ただし接続の可視化や全体レイアウトのための迂回は許容。**同じ箇所に重なるwireセグメントや、判読を妨げるシンボル・文字・配線の重なりは禁止**。ジャンクションなしの明確な非接続クロスは許容。
- **表示**：Reference/Valueは同じ部品のすぐ横に同じ向きで配置し、原則上段Reference・下段Value。同種部品の表示を揃え、他部品との取り違えを防ぐ。

詳細：[作図規約](references/drawing-rules.md)、[レビューで得た修正事例](references/review-lessons.md)。

## 完了時の要求

- 全体図と主要ブロックの拡大PNG/PDFを出して実際に確認。
- `$schematic-design`の品質ゲートを実施し、**修正した箇所で新たに別の作図ルールを破っていないこと**を報告。
- 回路図・ネットリスト・ERC・部品情報の変更検証を実施し、未検証の内容は明記。
- V4等の別スタイルは同時適用せず、比較するときはスタイル名/版を記録。

このスタイルは**初期版**。今後のV4比較や別回路の検証で変更される可能性がある。本人の好みを万人にとっての唯一の正しい作図法として扱わない。
