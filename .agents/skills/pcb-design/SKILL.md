# PCB設計ノウハウの抽出と実践

人間の判断を、配置・配線の候補を考案する手順へ整理する。本スキルは運用を用意した段階であり、検証済みの設計手法はまだ登録されていない。既存の検査閾値や禁止事項を、そのまま検証済みの設計ノウハウにしない。

## 分析から実践へ

[人間実演の手順](../../../docs/reviews/README.md#人間の修正実演から設計手法を学ぶ運用)に従う。人間の説明に数値化や厳密なアルゴリズムを要求しない。説明とCAD差分を照合し、次の順で方法を整理する。

1. 問題の認識。対象のネット・端子・帰路・周辺部品を特定し、どの配置関係や配線形状が問題かを示す。検出候補と確認済みの問題を分ける。
2. 判断の根拠。人間の発言とCADから確認できる事実を分け、変更した理由・優先した制約・維持した条件を示す。発言にない理由はCodexの解釈と明記する。
3. 配置・経路の考案。実演から読み取れる部品の相対関係、接続順序、通路、層選択、帰路を説明する。点の座標を写すのではなく、その関係を満たす案を作る手順へ変換する。代替案と採否理由も残す。
4. 実行可能な手順。操作範囲、作業順序、守る条件、失敗時の見直し箇所を記す。対象以外の配置・配線を変更する必要があれば、その理由と影響範囲を提示する。
5. 適用と検証。適用条件、例外、必要な電気・形状・画像検証、完了条件を定める。件数の減少だけで完了にせず、対象範囲の要修正残件と未承認例外を確認する。

解釈と実践方針を提示し、ユーザーの承認後にAI側の修正前データへ適用する。人間の修正済みCAD、差分、座標列をコピー・パッチ適用して再現しない。修正前後の差分を分析に使うことは認めるが、実践では承認された手順から配置・経路を考案する。同じ意図を満たす別解を認める。

## 比較と蓄積

人間とAIの結果を、同じ基準・同じ検査条件で比較する。失敗は、説明の不足、解釈の誤り、設計手法の問題、CAD操作・実装能力に分けて根拠を残す。区別できない場合は未確定とする。実機未測定の特性を、形状検査やDRCで実証したことにしない。

基板修正とノウハウには別々の人間判定を受ける。知見の各登録には、問題の認識方法、判断基準・優先順位、配置・経路の考案方法、修正手順、適用条件・例外、検証方法・完了条件を含める。個別の部品番号・座標・ネット名とCADコミットは固定履歴に残し、汎用手法には履歴へのリンクと手法の版を付ける。

未検証の知見は暫定とし、「再現」「応用」「予防」「汎用化」ごとに証跡と人間判定を残す。再現でOKでも、他の段階は未検証のままにする。最初の知見が得られた時点で必要な手法だけを本スキルに追記し、量が増えた場合に限り機能別のreferencesへ分ける。事例別ファイルは増やさない。

## 役割と保存先

- `pcb-pipeline`はCAD操作・連携・出力の参考。A-2ではKiCadを直接使い、atopileや無断の全体再生成を適用しない。既存の上流コピーは変更しない。
- 回路図の設計・検証は`schematic-design`、作図規約は`schematic-style-standard`に従う。
- ID、判定、履歴は`design-review-records`、独立環境と人間の編集保護は`design-workspace-management`に従う。
- [固定成果物規約](../../../docs/review_artifacts.md)を使う。再利用できる処理だけを`tools/design_review/`へ置き、一時コード・試行画像はGit管理外へ保存する。
