# 回路図作成・変更の共通スキル

## 用途と責務

新規回路図作成・既存図面の再配置・回路レビュー後の局所修正で用いる。**電気的接続と設計意図を保護し、人間が読める図面の検証を必須化する**。単にERC=0やネットリスト一致で「視認性が良い」と判定しない。

このスキルは**CADから独立した共通手順**。KiCadでの形式・CLIは例示であり、他CADでは同等の検証手段を選ぶ。

- 作図スタイルは別スキルを**1種類だけ選択**する。現時点では`$schematic-style-standard`（V3系）が選択可能。
- `$pcb-pipeline`は既存の上流スキル。**変更しない**。回路図の作図部分には本スキル＋選択スタイルを適用し、電気設計・製造・安全条件は既存の設計ルールと要求仕様を優先する。
- 設計・回路・PCB・製造の変更を混同しない。レビュー対象を変更する場合はブランチ/コミットと実施承認を確認する。
- 明示されていない技術要件や検証結果を推定で「合格」にしない。

## 作業前：作図契約を確定

1. **対象・基準**：元回路/ブランチ/コミット、CAD版、使用ライブラリ、図面の対象範囲と禁止変更範囲を記録する。
2. **作業の種類**を指定：`layout-only`（描画表現のみ）か、`electrical-change`（承認済み回路変更を含む）か。無指定なら既存回路では`layout-only`。
3. **スタイル**：選択したスタイル名と版、プロジェクト固有の例外指示、ユーザーのレビュー指摘を明示する。
4. **基準証跡**：回路図の複製、部品/ピン/ネットの一覧、可能ならERC・PDF/PNG、既存の設計状態を保存する。元設計・他ブランチを上書きしない。
5. **機能マップ**：入出力、電源系統、保護、発振、制御、パスコン、関連ネットなどを整理。接続の実体と作図位置を分けて考える。

既存の作業ブランチや元図の作図スクリプトを無条件に再実行しない。補助スクリプトには入力ハッシュ確認と非破壊的な再実行条件を付ける。

## 変更後の必須手順

**「作図できた」では完了しない。各修正バッチごとに以下を行う。**

1. **電気検証**：`layout-only`なら部品の属性・端子とネットの対応・ネット分割/統合が変更されていないことを確認する。電源シンボルやライブラリ図形に変更がある場合はXML全体のバイト一致に固執せず、既存実部品の各端子のネット、部品属性、承認された差分で比較する。
2. **ERC**：変更前後を同じCAD/同じ設定で検査。既存の無視ルールを無断追加しない。エラー数0でも機能・安全性・物理レイアウトは保証されない。
3. **スタイル回帰検査**：選択スタイルの「必須・原則・例外」のチェックを**今回変更した箇所だけでなく、影響のあった周辺ブロックにも**実施する。既存ルールの退行を記録する。詳細は[品質ゲート](references/quality-gates.md)。
4. **描画出力**：全体PDF/PNGと、変更がある機能ブロックの拡大図を実際に開いて確認する。名前・定数・ピン・線・接続点を判読できる倍率で確認する。
5. **設計データ保全**：PCB・BOM・製造データ・他ブランチ・ライブラリ等の変更禁止対象を差分で確認。必要ならSHA/オブジェクトIDで保全検証。
6. **証跡と報告**：適用スタイルと版、チェック項目の結果、未達成の例外と理由、ユーザー確認が必要な箇所を残す。レビュー台帳への記録が必要な場合は`docs/reviews/`のルールを使う。

## 自動検査と画像検査の責務を分離

- **機械検査向け**：重複・重なったwireセグメント、既知のシンボル回転、Reference/Valueの非表示・重複位置、端子接続差分、ERC結果など。解析ツールを**実際に実行した場合に限り**「自動確認済み」と記載する。
- **画像・意味理解が必要**：意図しない見かけ上の接続、電源ツリーの理解のしやすさ、ラベルを辿る負荷、配線の迂回の妥当性、非接続クロスの誤読可能性。
- **人間判断が必要**：例外的な作図判断、異なる設計者のスタイルの好み、回路全体の最終承認。

未実装の自動チェッカーが存在するかのように報告しない。**自動化できる条件は次期の検査スクリプト候補**として記録し、現時点は既存の設計用検証スクリプトやCAD/画像レビューで実施する。

## 優先順位と例外

1. 電気的整合性、変更範囲の保護、規格・安全上の必要条件
2. 確実に検証可能な作図の禁止事項（重複線分、誤接続に見える交点、文字と図形の判読不能な重なり）
3. 選択スタイルの一貫性（電源/GND、部品シンボル・向き、表示）
4. 回路機能の追跡と適切な部品の関係・ブロック構成
5. 図面のコンパクトさ、迂回の最小化、整列、空白の最適化

上位の条件を守るために下位を譲歩してよい。ただし、**作図上のトレードオフを理由に既存の必須ルールを無言で破らない**。原則違反が必要なら箇所・理由・影響・代替案を残す。設計者から明示的に修正された好みは、以後の同じ作業で優先する。
