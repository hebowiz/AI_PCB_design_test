# 品質ゲート・回帰防止の運用

## ルールの区分

| 分類 | 意味 | 取り扱い |
|---|---|---|
| HARD | 電気的整合性と禁止される誤解を生む表現 | 未解決なら原則「完了」不可 |
| STYLE | 選択したスタイルの基本規約 | 必須に近いが、部品・機能に基づく例外は記録して許容 |
| PREFERENCE | できれば満たす最適化目標 | 他の要件を破らず最善を探す。数値だけで採点しない |
| HUMAN | 最終的な可読性・設計判断 | AIがユーザー承認を代行しない |

例えばGNDへ接続するパスコンの縦向きは`STYLE`、IC端子への近接は`PREFERENCE`。**近接させるために横向きへ変えてはいけない**。通例に合わない例外には理由を残す。明示のレイアウト方針があればそれを優先する。

## 修正バッチごとの回帰確認

- [ ] 対象ブランチ・コミットと作業範囲が固定されている
- [ ] 保存済み/修正後の部品・ネット比較が`layout-only`の範囲で一致（または承認差分のみ）
- [ ] ERC条件が不変で、新規違反なし
- [ ] 同一ネット/異なるネットにまたがる重複したwireセグメント、同一直線上の二重描画なし
- [ ] 図面上の重なりで別ネットが接続されていると誤読させない（交点とジャンクション、シンボル、ネットラベルを画像でも確認）
- [ ] **選択スタイルの全項目を再確認**：PWR_FLAGの向き、関連信号の並走と交差、パスコンの向き/GND、電源ツリー、Reference/Valueと記号
- [ ] 電源配線・バイパスC・ESD枝の配置意図が変更後も表現されている
- [ ] 不必要に長くなった配線・無駄な折返しがないか確認。長さが増えた場合は理由を記録
- [ ] 元のCAD/BOM/PCB/Gerber等の保護範囲に差分がない
- [ ] 全体図と影響ブロックの拡大図を確認し、検証証跡と残件を保存
- [ ] 最終的なユーザーOKは、ユーザーの明示的な判定だけを使う

## 作図を直したら別ルールを壊す問題への対策

同じ変更で一つの項目を改善しても、他の項目が悪化しうる。例：パスコンを近づける→横置き化、GNDをまとめる→長い引き回し、ペアを並走させる→不要な2重交差、注記を移す→PWR_FLAGと文字が重なる。

次の順序を繰り返す：

1. **局所変更**。修正内容以外は動かさない。
2. **機械検査**。接続・ライブラリ・属性の一致、ERC、必要な座標上の幾何検査。
3. **局所の見た目**。特に修正した部品・同じ信号の両端・周囲のシンボル。
4. **全体の見た目**。ブロック配置、電源の流れ、用紙収まり、表示の統一。
5. **ルール再照合**。修正した意図と別に、PWR_FLAG、パスコン、交差、線重複、文字対応を再確認。
6. **例外/残件を記録**してからコミット。

変更箇所だけを見て「OK」とせず、影響ネットと隣の部品までを見る。重要条件の自動検査が未実装なら、「未確認」として記録するか実際に画像・CADデータで確認する。

## 可読性スコアの扱い

線分数・ネットラベル数・同じ長さの線の総計だけで可読性を数値化しない。実線を多くすると線の長さやクロスは増える場合がある。局所のつながりが追え、回路の機能が把握できるかを最終判断に含める。
