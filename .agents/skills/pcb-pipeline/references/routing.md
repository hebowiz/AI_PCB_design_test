# Freerouting で自動配線する

## 版と Java

2.4 系は Java 25 でないと起動しない。`UnsupportedClassVersionError` が出たら
これ。Java 21 で動かすなら 2.1.0 を使う。

```sh
curl -sL -o ~/tools/freerouting-2.1.0.jar \
  https://github.com/freerouting/freerouting/releases/download/v2.1.0/freerouting-2.1.0.jar
```

## ヘッドレスにする方法は 1 つだけ

コマンドラインオプションに GUI の切り替えは無い。**作業ディレクトリの
`freerouting.json` で `gui.enabled` を false にする**のが唯一の方法。
指定しないとウィンドウが開いて、そのまま返ってこない。

```json
{ "gui": { "enabled": false }, "profile": { "email": "", "id": "" } }
```

一時ディレクトリにこの設定を置き、そこを作業ディレクトリにして起動する。

```sh
java -Djava.awt.headless=true -jar freerouting.jar -de in.dsn -do out.ses -mp 30
```

主なオプションは `-de` 入力、`-do` 出力、`-mp` 最大パス数、`-mt` スレッド数、
`-dr` デザインルール。終了時に配線長、ビア数、クリアランス違反数を JSON で出す。

**クリアランス違反だけ見ても足りない**。ルータは違反 0 のまま接続を諦める。
`items.incomplete_count` と、各パスの `(N unrouted)` を見る。ここを見落とすと、
KiCad の DRC まで気づかない。`scripts/check_route.py` が失敗させる。

ベタで完成させるつもりの GND は、ルータが 1 本残すことがある。その分だけ
`ALLOW_UNROUTED` で許すが、**本当の判定は DRC の未接続 0** のほう。

## 引き直す前に剥がす

前回の配線は配置を変えても残る。残ったまま DSN を出すと、ルータは既存配線として
受け取り、いまの配置に合わない銅を避けようとして**接続をいくつか諦める**。
配置や回路を変えたら、ロックしていない配線を全部剥がしてから DSN を出す。
ベタも剥がす。理由は次節。

## ベタは配線の後。両面に置く

KiCad はゾーンを DSN に `(plane <ネット> (polygon ...))` として書き出す。
**2 層基板で先にベタを置くと、ルータが信号を通す場所を失う**。両面を埋めた
状態で回す と、ほとんど何も配線されないまま違反だけが残る。

配線が終わってから流し込む。そのとき**両面に置く**。片面だけだと、反対の層に
残った GND の切れ端がベタに届かず、DRC が未接続として拾う。

取り込んだ後は必ず塗り直す。古い塗りのままだと新しい配線とぶつかって
クリアランス違反が大量に出る。

## 配線の前と後

**前に置くもの**。基板外形、部品配置、配線禁止領域。無線モジュールの
アンテナ下に銅を置かせたくないなら、パッドの無い側を囲むルールエリアを
作ってから DSN を出す。KiCad はルールエリアをキープアウトとして DSN に載せる。

**後に置くもの**。ベタ塗り、特殊形状の銅。先に置くと DSN が大きくなり、
ルータが planes を持て余す。SES の取り込みは配線とビアしか触らないので、
取り込んだ後に流し込んで問題ない。

## 大事な線は手で引いて固定する

全部ルータに任せてよいのは、遅くて単純な回路だけ。電源の帰路、アナログの
高インピーダンスノード、発振子の周り、差動ペアは先に手で引く。**引いたら
必ずロックする**。ロックしない既存配線は `(type route)` として出るので、
ルータが引き直してよいものと見なし、実際に引き直す。

手順と、各段階で確かめられること。

1. KiCad で手配線する。
2. その配線をロックする。選択して Edit > Properties、または
   `track.SetLocked(True)` をスクリプトで。
3. DSN を書き出す。ロックした配線は `(type fix)`、それ以外は `(type route)`
   になる。`grep -c "(type fix)"` で本数を確認できる。
4. Freerouting をかける。fix の線には触らない。**SES にはその線が現れない**。
   ルータが引いたものだけが session に入るため。
5. SES を取り込む。取り込みは配線を全部置き換えるわけではないので、
   ロックした線はそのまま残る。取り込み前後で本数を数えれば確かめられる。

4 と 5 は直感に反する。SES に無いから消えると思いがちだが、消えない。

## 配線できないとき

- 外形が無い。境界が無いと何も配線されない。
- ネットが 1 パッドしかない。配線する相手がいないだけで、異常ではない。
  マイコンの未使用ピンは全部これになる。
- 部品が原点に重なっている。`ato build` の直後は全部 (0,0) にいる。
  配置してから DSN を出す。

## Freerouting 2.1.0 の実際の振る舞い

**パス数の上限は効かない**。`-mp` も `freerouting.json` の `router.max_passes` /
`job_timeout` も無視され、未配線が 0 になるまで回り続ける。**SES は正常終了した
ときにしか書かれない**。`timeout` で止めても SIGINT を送っても出てこない。
`route.sh` は外から `timeout` で包み、ログを `out/router.log` に残す。

**未配線が一定数で止まったら、構造的に引けない所がある**。パスを増やしても減らない。
ログは本数しか言わないので、次の順で特定する。

1. 配線前に DRC を回す。部品の重なりや、固定配線とパッドの間隔不足はここで出る。
   ルータはこれを黙って「引けない」にする
2. SES が出たら取り込み、ベタを塗って DRC の未接続を見る
3. SES が出ないなら、DSN の `(network` からネットを間引いて短時間回し、
   未配線数の変化で絞り込む

**信号層のベタは他ネットの障害物にならない**。KiCad はゾーンを
`(plane ...)` として出すが、ルータは平気でその上に他のネットを通す
(電源のベタを信号が横切って二つに割る)。配線の間だけ、ベタの輪郭に
配線・ビア禁止の禁止領域を置き、SES を取り込んだら外す。

**F.Cu の禁止領域の下を B.Cu で通した配線は SES から落ちる**。ルータは引けたと
思っているのに、SES には長さ 0 の点しか残らない。禁止領域で層を追いやらない。
裏へ回したい線は、上下にビアを置いた B.Cu の固定配線にして渡す。

**信号層のベタから、ベタの外のパッドへは引かない**。分圧抵抗やレギュレータ入力など、
ベタのネットの小さな枝が未配線で残る。ベタの縁に 0Ω を置いて片方のパッドを
ベタに埋め、枝を別ネットにする。取り出し点が 1 点に決まるので、電圧検出の
ケルビンタップにもなる。

**ルータの出力には掃除が要る**。

- 同じ片を往復で 2 本重ねて書くことがある (両層に)。重複は 1 本にする
- 行き止まりの片を残す。端が同じネットのパッド・片の端・片の途中 (T 字)・ビア・
  ベタのどれにも触れていない片を、無くなるまで繰り返し消す。**T 字接続を
  見落とすと、繋がっている線まで消す**
- 同じネットの穴どうしの間隔を見ないので、GND ビアを固定ビアや端子の穴の
  すぐ隣に打つ。穴間隔を割るルータのビアは消す (内層の GND 面に繋がるので影響しない)

**基板の縁のクリアランスを知らない**。DRC の縁クリアランスに掛かる。
配線の間だけ、縁に幅 0.6mm ほどの禁止領域を置く。

**毎回結果が違い、まれに数本残す**。ベタと内層面で完結する GND 接続も
「未配線」に数えるので、ルータの数字では合否を決めない。DRC の未接続 0 で判定し、
駄目なら pre からやり直すループを Makefile に書く (3 回で足りる)。

**所要時間**は、100 部品・4 層で 1 回 5〜9 分。

禁止領域の出し入れと掃除の実装は `scripts/finish_board.py` の
`pre()` と `clear()`。やり直しのループはこう書く。

```make
ROUTE_TRIES ?= 3
routed:
	@for i in $$(seq 1 $(ROUTE_TRIES)); do \
		$(MAKE) pre unroute dsn && ($(MAKE) route || true) && \
		$(MAKE) ses post && $(MAKE) drc && exit 0; \
	done; exit 1
```

## ネットクラスとピンの間隔

**クリアランスを部品のピン間隔より大きくすると、そのピンから線が出せない**。
0.5mm ピッチの MSOP はパッド間 0.22mm、SOT-23-8 は 0.2mm。ここに 0.25mm の
クラスが掛かると、ルータは黙って諦める。配線前の DRC で自分のパッド同士の
違反として出るので、それを見てクラスを決める。4 層の JLCPCB は 0.09mm まで作れる。

**線幅も同じ理由で太くしすぎない**。主電流はベタで流すなら、電源クラスの線は
ベタの外の細い枝 (分圧、レギュレータ入力) にしか使われない。0.5〜0.6mm で足りる。

**ゾーンの既定クリアランスは 0.5mm**。ネットクラスより大きいので、ルータが
引いた線とベタの間が DRC 違反になる。ゾーンを作るときに合わせる。
