# 製造業者に発注する

業者を問わない確認事項。業者ごとの書式・下限・料金は `<業者>.md` にある
(いまは `jlcpcb.md` だけ)。

## 出すファイル

`make fab` が `out/<FAB>/` に 3 つ書く。

| ファイル | 中身 | 作るもの |
| --- | --- | --- |
| `gerber.zip` | 製造レイヤとドリル | `kicad-cli pcb export gerbers / drill` |
| `bom.csv` | 型番と部品番号 | `scripts/fab_files.py` が atopile の BOM を業者の列名に直す |
| `cpl.csv` | 実装座標 | `scripts/fab_files.py` が `kicad-cli pcb export pos` を業者の列名に直す |

実装座標は `kicad-cli pcb export pos --format csv --units mm` の出力の列名を
変えるだけでよい。ガーバーと同じ座標系になる。原点をずらす指定は、ガーバー側と
揃っていない限り付けない。

**ガーバーは製造レイヤだけに絞る**。Fab、Courtyard、User レイヤが混ざっていると
基板外形と誤認されることがある。銅層は基板の層数から決まる (`scripts/gerber_layers.py`)。

**部品を変えたら `make fab` を流し直す**。`make all` はガーバーまでで、
`out/<FAB>/` の BOM と実装座標は前回のまま残る。部品を差し替えて配線まで
やり直したのに、BOM だけ旧型番のまま、ということが起きる。アップロード前に
BOM の型番を `.ato` の `lcsc_id` と突き合わせる。

## 製造能力に収まっているか

KiCad の DRC はプロジェクトの規則で見ているだけで、業者の下限とは別物。
業者の下限を規則として書いた `.kicad_dru` を、基板のコピーに当てて DRC する。
本体の基板には置かない (ネットクラスより緩い規則が設計を上書きする)。

```sh
mkdir -p /tmp/fab && cp board.kicad_pcb board.kicad_pro /tmp/fab/
cp references/fab/jlcpcb-4layer.kicad_dru /tmp/fab/board.kicad_dru   # 基板と同じ名前にする
kicad-cli pcb drc --severity-all --format json -o /tmp/fab/drc.json /tmp/fab/board.kicad_pcb
```

エラーが 0 なら製造はできる。警告のうち見るのは `text_height` と `text_thickness`
(シルクが潰れる)。`silk_over_copper` と `silk_overlap` は、EasyEDA の外形線が
隣のパッドや外形にかかっているもので、パッドにかかった分は業者が削る。
部品番号 (`Reference field`) が絡んでいるものだけ直す。→ `scripts/place_labels.py`

## 設定で間違えやすいところ

**表面処理**。多くの業者で既定は HASL。露出銅を電極や接点として使うなら ENIG を選ぶ。
HASL は半田が盛られて凸凹になり、酸化もしやすい。

**スルーホール部品**。SMT だけの安いコースでは載らない。手はんだのオプションを
付けるか、その部品を実装対象から外す。`HAND_SOLDER` に atopile のインスタンス名を
書くと、`scripts/fab_files.py` が BOM と実装座標の両方から外す
(`HAND_SOLDER ?= j_in,j_out,j_mcu`)。部品番号は作り直しで変わるので名前で書く。

**レジストの大穴**。意図的な露出銅は製造前確認で指摘されることがある。
意図したものだと答える。

## 部品を替えるとき

- 部品を替えたら `make fresh` からやり直す (`atopile.md`)
- **パッケージが小さくなるとパッドが座標で決めたベタから外れる**。スナバ抵抗を
  1206 から 0805 にしたら、SW 側のパッドが SW のベタの縁に 0.1mm 届かなくなった。
  DRC はその 1 本を未接続にし、ルータは何度やり直しても引けない (3 回とも失敗)。
  パッケージを変えたら、ベタに乗せるつもりのパッドの範囲とゾーンの座標を
  配線の前に突き合わせ、配置表で部品を寄せる
- atopile の部品検索に無い型番 (LCSC に新しく載った同等品など) は `ato create part` で
  取り込めない。その部品は替えずに残す
- 耐圧や DC バイアスで決めた電源のコンデンサは、安い品に替えない。小型の X5R に
  なると実容量が大きく落ちる

## 実装してもらう前に必ず見ること

**極性のある部品で、フットプリントにもシンボルにもデータシートにも極性の
記載が無いものは、実装対象から外して手で付ける**。電池ホルダーによくある。
EasyEDA 由来のシンボルはピンが 1 と 2 としか定義されておらず、どちらが正か
分からない。実装後に気づいても直せない。

タンタルやアルミ電解は、フットプリントの極性帯がどちらのパッド側にあるかを
確認する。慣習では 1 番が正極。逆に付くと短絡故障して発熱する。
極性の無いセラミックで置き換えられるなら、そのほうが安全。

**3D モデルと実装属性**。`scripts/check_models.py` で、3D モデルのオフセットが
ずれた部品と、SMD なのに属性が through_hole の部品を出す。前者は 3D レンダで
部品が別の部品の下に潜って見えるだけだが、フットプリントの出来が悪い印なので
別の型番に替える。後者は `kicad-cli pcb export pos` に `--smd-only` を
付けると実装座標から落ちる (属性で判定するため。付けなければ載る)。

**回転角**。アップロード後のプレビューで IC と極性部品の 1 番ピンを見る。
業者のライブラリとフットプリントの向きの約束が違うと、全部品が 90° や 180° ずれる。

**在庫**。発注時に実数を見る。atopile の部品 API の在庫数は当てにならない
(全部品が在庫 0 と返ってきたことがある)。

## 新しい業者を足す

調べるもの: 製造能力 (線幅・間隔・ビア・シルク)、受け付けるガーバーとドリルの形式、
実装の BOM と実装座標の列名、部品の調達方法 (業者の在庫から選ぶか、型番で調達か)。
分かったら `<業者>.md` と `<業者>-<層数>.kicad_dru` を書き、`scripts/fab_files.py` の
`FABS` に列名を足す。
