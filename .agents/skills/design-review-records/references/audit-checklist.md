# 議事録再整理・レビュー記録の監査

## 変更前の保護

1. 現行`main`のコミットIDと`docs/reviews/`内対象ファイルを固定する。作業は管理担当セッション/Worktreeで。
2. 台帳を構造化し、全行のID、指摘者、工程、指摘日時、重要度、現在の状態、判定、判定者・判定日時、基準設計・修正後コミットをスナップショットにする。
3. 個別詳細とバッチレポートを読み、各IDの最終的な回路変更・検証・未解決事項を抽出。**文面修正前に「最終対応」と「途中案」を分けておく**。

## 変更する範囲

- 共通台帳：15列/1件1行と全IDを維持。長い対応内容・証跡欄を簡潔な最終状態に修正。既存日時の粒度を勝手に変えない。
- 詳細：技術背景、計算、候補比較、承認された変更、失敗とやり直し、最終判定の履歴を残したまま、重複説明・冗長な日時取得方法・同じ結論の再掲を整理。
- バッチ資料：当時の一括調査・修正・判定を記録する。**当時未判定だった記録を「その時点ですでにOK」に書き換えない**。
- README/テンプレート：今後も同じ形式で記録できるように更新。ただし台帳の項目数や意味はユーザーの指定なく変更しない。

## 差分の検査（手動でも自動でも実施）

- [ ] 既存ID・件数・順序・15列・1行1指摘に変化なし
- [ ] 各IDの指摘者、工程、対象箇所、重要度、指摘内容の**意味**に変化なし
- [ ] 各IDの状態・判定・判定者・判定日時と、過去のNG/再判定が保持されている
- [ ] 技術判断とその根拠、修正しなかった理由、未検証事項が保存されている
- [ ] 各IDの**最終対応の要約**が個別詳細/設計コミットと一致。特にR-0002、R-0004をチェック
- [ ] 変更先ブランチ・固定SHA・文書内リンクが維持され、実在する
- [ ] 全行が読みやすくなり、判定日付の不要な重複と毎回の時刻取得説明が消えている
- [ ] 異なる時刻を一律に「同じ日時」とみなして統合していない
- [ ] `git diff --check`、マークダウン表の構文・リンク検査が合格
- [ ] CAD・PCB・BOM・Gerber・スキル以外の設計データに差分がない

※ 実際に検査していない項目を「確認済み」にしない。検査スクリプトの存在を仮定しない。

## 例外・エスカレーション

技術報告とGitコミットが食い違う、正しい時刻が確認できない、相反する設計承認がある場合は、原資料で確認できた範囲だけ報告し、推測で「修正」しない。必要ならユーザー確認項目として残す。

文章整理のために技術的な判断の証拠を削除せず、複数の意思決定の経緯を単一の結論に潰さない。

## 報告

変更件数と代表的な改善例、最終対応の訂正事項、変更していない情報（ID・承認・設計成果物）、未検証事項、コミットIDを短く報告する。内部のトークン・スクリプト・細かい時刻取得説明はユーザー向けの完了報告に列挙しない。

## 固定保存方式の追加確認

- 新規のレビュー別reports・details・batches・evidenceが増えていないか。
- manifestの入力ハッシュと対象CADが一致し、未実行項目に前回のファイルが残っていないか。
- 根拠をGit管理外にだけ残していないか。固定履歴・固定成果物から判断と再試行を追えるか。
- 過去証拠のリンクが完全SHAを含み、更新前の固定ファイルを復元できるか。
