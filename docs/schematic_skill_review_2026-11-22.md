# 回路図の作図スキル追加に関する検討記録

記録日：2026-11-22 JST

## 背景

A-2のV0→V3-polish、回路レビューR-0001〜R-0015の経過では、既に合意した作図規則（コンデンサの向き、ピンとの関係、文字位置など）が**後続の局所修正で崩れる**ことがあった。一方、回路図上のUARTの明確な非接続クロスやUSB配線の迂回はユーザーが許容し、交差・長線を一律禁止すべきではないことも分かった。

## 設計方針

**ルールだけを列挙せず、ルール間の優先度と修正後の回帰検査をスキルに含める。**

- **共通スキル**：`schematic-design`。接続保全、ERC、画像確認、変更前後の規約の回帰、例外履歴。
- **V3系のスタイル**：`schematic-style-standard`。PWR_FLAG上向き、wire重複禁止、短分岐、ペア交差最小化、電源/GND、縦置きパスコン、文字配置。
- `pcb-pipeline`は初回導入のMIT版をそのまま保持。今後のV4では別スタイルスキルを追加する予定。
- 具体的な部品・接続の設計変更（ESD321、FT232HのLDO、負荷容量など）と**作図品質**を混同しない。

## 縛りすぎない仕組み

- 不正接続・誤認しやすい配線重複などは**必須改善**。
- スタイルの一貫性は**基本として強く優先**。例外には根拠を残す。
- 線の長さ・交差数・部品の近さは**最小化目標だが絶対条件にしない**。複数の作図ルールが衝突するときは電気的正確性と可読性を優先する。
- 人間のレビューとフィードバックを引き続き受け付け、再発する指摘は規約・検査項目に昇格させる。

## 検証状況・今後

今回は**スキルの初期文書と適用ガイドを作成する段階**。このコミットにより、V3系作図規約とR-0009〜R-0015の一般化した教訓を記録する。CAD図面の再生成、KiCad ERC実行、自動図面リンタの実装、別回路でのスキル適用確認は実施していない。各作業におけるスタイル適合は、実際に図面/検証データを確認するまで未検証として扱う。

今後は検査スクリプトの段階的な実装（重複wire、PWR_FLAG向き、コンデンサの向き/接続、文字位置、重要ネットのペア交差）と、新規回路による再現試験を検討する。
