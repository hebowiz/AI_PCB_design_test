# 将来構想：設計ノウハウを蓄積するAIハードウェア設計エージェント

記録日：2026-11-22 JST  
状態：**構想段階・随時改訂する草案（設計仕様・実装の確定事項ではない）**

## 目的

回路設計、回路図作図、基板設計におけるエンジニアの知識・判断基準・試行錯誤・レビュー結果を継続的に蓄積し、個人の設計思想に近い判断と作業を行えるAI設計環境（「設計者の分身」）を目指す。CAD操作を自動化するだけでなく、条件が足りない場合に重要な制約を見つけ、優先順位を付け、適切に根拠・仮定・未検証事項を表明できることを重視する。

この文書は**検討中に変更してよい見通し**を整理するもの。実装開始・完成保証・製造承認を意味しない。

## 1. 設計知識を3つの能力に分ける

| 能力 | 蓄積する内容 | 品質確認の例 |
| --- | --- | --- |
| 回路設計 | 要求分析、ブロック構成、型番と定数の選定、信号/電源条件、保護、設計余裕、例外・根拠 | データシートとの照合、計算、回路機能レビュー、必要な実測 |
| 回路図作図 | 機能の流れ、実線とネット名、シンボル、電源・GND、パスコン、注記、Reference/Value | ネットリスト一致、ERC、画像の視認性、人間レビュー |
| 基板設計 | 外形・固定部品・部品高さ、重要ネットの配置配線、信号品質、リターンパス、熱/EMC、製造性 | DRC、レイヤー/スタックアップ照合、CAM、解析・実機試験 |

単なる結果ではなく、**ルール・採用理由・優先順位・適用条件・例外・検証証拠・失敗例・人間による訂正**まで記録する。一般的な技術要件と個人の作図上の好みを混同しない。推測と実証結果も区別する。

## 2. スキル構成と選択式の作図スタイル

既に導入した`.agents/skills/pcb-pipeline/`は**元の状態と出典を保持**し、当面は改変せず、追加スキルは別ディレクトリで管理する。

構想上の責務：

- **共通設計・検証スキル**：接続/属性の保全、出力のトレーサビリティ、変更差分の確認、ERC/DRCと実証の区別
- **回路設計スキル**：要求からの回路構成、重要条件の抽出、部品/回路/電力条件の検討
- **回路図作図スキル**：接続の可視化、機能的配置、可読性の自己評価、CAD図面出力
- **基板設計スキル**：機械的制約・優先ネット・基板実装の技術的判断
- **CADアダプター**：KiCad/atopile/EasyEDAなどCAD固有のデータ操作と検証。作図規約とCAD APIを分離する

作図には**選択式スタイル**を用意する案：

- **標準／汎用**：A-2 V3系を基に整理する規約（電源・GND、機能ブロック、実線の使用など）
- **個人向け詳細スタイル**：今後のV4で試す独自規約。V3と異なる部分をスタイルとして分離する
- **共通ルールを重複させない**：接続・ERC・図面確認などは共通に保持する。競合するスタイルは同時に適用せず、案件単位で明示選択する

スキルのディレクトリ名・階層・優先順位の実装は、V4の結果を踏まえて決定する。**今回、新しいスキルファイルは作成しない。**

## 3. 案件ごとの仕様は編集可能な構造化リストへ

長文プロンプトだけではなく、設計入力を**編集・保存・差分比較・再利用できるリスト**として扱う。将来的にはGUIで編集し、内部形式はJSON/YAMLなどの構造化データ＋Schemaを候補とする。

入力カテゴリの例：

- **回路・機能**：用途、電源電圧、動作モード、通信方式、速度、IO、信号条件、消費電力
- **基板**：外形、板厚、層数、銅厚、材質、構造、製造先スタックアップ
- **部品**：指定型番、代替可否、コスト、実装面、高さ、調達、禁止パッケージ
- **配置/機構**：コネクタ・スイッチ・LED・アンテナ等の固定位置、禁止領域、高さ制限、筐体との干渉
- **配線**：差動対、インピーダンス、配線長/間隔、基準面、ビア/層変更、優先配線、リターンパス
- **検証**：必須の計算・解析・レビュー・試験、合格条件、製造可能性

各入力に、値/単位、必須・推奨、**確定・暫定・未定**、根拠（ユーザー指定/データシート/AI提案）、対象範囲、変更履歴、承認状態を持たせる案。AIが未指定の重要条件に気づいたら、**独断で確定せず候補を追加**し、条件に応じて承認待ち/暫定値/設計保留を区別する。

**設計要求（案件データ）と設計ノウハウ（スキル）は別管理**。例えばUSB差動90Ωの注意をAIが認識しても、実際の製造スタックアップ・線幅・間隔・優先配線への反映と検証がなければ「満たした」とは扱わない。

## 4. 特殊外形と筐体・固定部品の制約

矩形基板だけでなく、筐体や既存機構の影響を受ける基板を想定する。

- **候補入力**：基板外形や穴のDXF/既存KiCad PCB、筐体/部品のSTEP、部品ごとの座標・回転・面・高さ、Keepout/Keepin領域、ネジ/リブ/ボスなど。
- **座標定義**：原点、単位、軸方向、基板の表裏、部品フットプリントのアンカー位置、変換ルールと参照ファイル版を明示する。
- **固定/可動の区別**：機構から決まる部品は位置・角度・搭載面をロックし、調整可能な部品だけ最適化する。例外はユーザー承認を要する。
- **作業順序**：外形・穴・固定部品・禁止領域→関連回路を配置→重要配線を先に設計/保護→一般配線→電気/機構/製造条件を確認。
- **段階的な実装**：2D外形・固定部品制約の確実な適用から始め、STEPからの機構空間抽出や3D干渉確認はCAD連携・モデル精度を含めて別途検証する。STEP読込だけで完全な機構適合を保証しない。

## 5. 望ましい設計ワークフロー

1. **仕様入力**：ユーザーが構造化リスト、図面、CADファイル、固定制約を登録。
2. **制約の発見と優先順位付け**：AIが規格・データシート・過去設計の知識から未指定の必須項目と未確定情報を抽出し、根拠を示す。
3. **回路設計**：機能・定数・部品選定・保護とトレードオフを記録。
4. **回路図作図**：共通規約＋選択したスタイルに従い、電気的同一性と読みやすさを検証。
5. **基板設計**：外形と機構制約を固定し、重要部品・配線・電源/GNDを優先。
6. **検証**：自動検査（ERC/DRC/ネット照合）と技術レビュー（電気特性、信号品質、熱/EMC、製造性）を分離。
7. **レビューと学習のための記録**：指摘事項→設計判断・理由→修正前後→検証結果を保存。確認されたノウハウだけをスキル候補へ昇格させる。

必要な設計パラメータが得られない場合の**停止条件・暫定設計の範囲・ユーザー承認が必要な操作**を明文化する。回路を製造発注する判断は独立した承認工程とする。

## 6. 開発・検証・履歴

- Gitによる入力仕様、スキルの版、各設計成果物、判断ログ、画像、検証データの対応付けを維持する。
- 元設計を保持し、新規試験は別ブランチ/Worktreeで実施。回路図だけの作図改善とPCB品質改善は別の評価軸にする。
- AIが提示するノウハウが「自発的に見つけたもの」か「人間が具体的に指示したもの」か区別する。
- 新スキルは**別案件・別回路で再現性を試してから**有効性を判断する。
- 秘密情報、未公開の社外/社内回路、ライセンス制約のあるデータは公開リポジトリへ配置しない。
- 自動生成のERC/DRC合格は設計の性能保証・製造承認ではない。

## 7. 直近の状態と将来の判断ポイント

- A-2のV3-polishは作図表現の**レビュー候補版**。ユーザーの主観評価は約95点。正式な回路電気レビュー・PCBレビュー・実機検証はこれから。
- 次の行動候補は**V4の独立した詳細作図指示の実験**、または**回路内容の人間レビュー**。両方とも未着手。
- V4で良い成果が出たら、V3標準系との差を抽出して選択式の作図スタイルへ分離する。共通スキルやCADアダプターの設計は、その比較を踏まえて判断する。
- 仕様編集UI、DXF/STEP取込、固定配置/高制約配線の制御、CADごとのデータ変換/可視化/機構検証は今後の試作検証テーマであり、現段階で動作実証はしていない。
