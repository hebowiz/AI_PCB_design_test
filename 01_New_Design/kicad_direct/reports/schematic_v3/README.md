# A-2 回路図視認性改善 V3

V2の機能ブロックと実線接続を引き継ぎ、GNDの局所化、電源記号の統一、ペア信号の並走、IC周辺のコンデンサ配置、電源生成の分岐表示を改めました。単一のA2シートを維持しています。

既存の58部品・207端子・58ネットについて、部品属性と接続関係の一致を確認しました。V2の複製とV3の両方でERCを実行し、エラー・警告は0件でした。読みやすさの評価はAIによる画像確認であり、人間による設計レビュー・承認は未実施です。

## ベースと変更範囲

ベースは指定されたV2の89093caab59e9e6897808d0fd020dd2c689ba450です。独立Worktreeでexperiment/A2-schematic-v3を作成しました。作図の入力はこのコミットの回路図です。V0・V1・V4の作図結果は入力に使っていません。

変更した設計ファイルはa2_usb_uart.kicad_sch、電源記号用の新規ライブラリ、sym-lib-tableです。既存の部品シンボル定義を変更せず、元の設計生成スクリプトも実行・変更していません。V2の作図関数をV3用フォルダに複製して利用しました。既存回路図にある部品・ピンのUUIDも維持しています。

基準コミットの531ファイルについてGitのblobを比較し、許可された変更対象以外に差分がないことを確認しました。PCB、部品表、製造データ、既存ライブラリ、V2の検証記録はこの保護対象に含まれます。main・V1・V2・V4へのマージやpush、製造発注は行っていません。

## 電源記号とERCの扱い

標準power.kicad_symを調べたところ、GNDは下向き三角形でした。円を含む候補には+VDC、-VDC、ACなどがありますが、横棒が円の外まで貫通する指定形状とは異なりました。新しい電源記号は円・横棒・接続軸で構成し、power globalとpower_in端子を持たせています。GND記号も同じ電気的構造とし、U1の2.54mmピッチに収まる小型三角形にしました。既存シンボルの形状を編集したものではありません。

新しい電源記号の追加により、SW2とSW3の後段にもERC上のpower_in端子が生じました。機械スイッチの受動端子を越えて電源出力の型は伝わらないため、後段2ネットに#FLG05と#FLG06を追加しています。円形の電源記号は別に設けており、PWR_FLAGを電源記号の代用品にはしていません。

この2個のフラグは、スイッチON時の給電元が存在するというERC上の宣言です。OFF時にも給電されることや、実際に5Vが出ることを保証しません。図面にもこの前提を注記しました。既存4個のPWR_FLAGは属性・UUIDを維持しています。実回路の部品追加はありません。

途中で後段の記号をpassive端子にする方法も試しましたが、この構造では期待する電源ネット接続にならず、未接続エラーが出たため採用していません。最終形は全電源記号をpower_inに統一しています。

## 画像による評価

初回の全体図、2回目の拡大図、修正後の拡大図と全体図を確認しました。電源記号の円に縦配線が重なって見える箇所、U1のGND三角形に近すぎる内部電源配線、電源見出しとUSB5V表記の近接を修正しています。C19とU4、C21とU6、C15とU5の距離も、この確認過程で縮めました。

電源生成はUSB5Vから3つのICへの分岐を目で追えるようになりました。GNDの長い折り返しが減り、U4の帰還抵抗と電圧選択、U6のQOD抵抗の関係を残せています。UARTの2か所の非接続クロスと、LED・EEPROMの局所接続も維持しました。

一方、U1の左側には電源・信号の非接続交差が残ります。全体を画面に収めると文字が小さく、ピン番号や値の確認には拡大が必要です。C3〜C6は個々の物理ピンに一対一で対応させた配置にはなっていません。人間の追跡時間や誤読率は測定しておらず、AIによる目視判断と電気的同一性の機械検査を分けて扱います。

## 作業時間と再実行

時刻を確認できる最初の操作は、Git reflogに残る2026-11-20 21:47:58 JSTのWorktree作成です。指示の読込はその前に行いましたが、開始時刻を採取していません。timing.jsonにはこの記録時刻から成果物完成までの経過時間を保存します。総着手時間としては、この時間に未計測の指示確認時間が加わります。今回の記録上の時間は17分5秒です。V2の17分14秒とは計測開始条件が完全には一致しないため、速度の優劣を断定しません。

Windows、PowerShell 7.6、KiCad 10.0.8、KiCad同梱Python 3.11.5、pdftoppmで作業しました。作図スクリプトはV2複製を入力とし、現在の回路図が基準版または直前のスクリプト出力と一致するときだけ上書きします。手作業後の無断再生成を避けるための検査です。

検証だけを行う場合はverify_v3.py、出力だけならexport_v3.pyを実行します。layout_v3.py --applyは回路図を書き換え、追加記号などのUUIDを再発行するため、確認目的だけで実行しないでください。再作図した場合は、出力・検証・画像確認をすべてやり直す必要があります。

ERCは実機動作や製造性の保証ではありません。EEPROM設定やハードウェア試験など、元設計の未検証事項は今回の表現変更では解決していません。PCBを変更していないため、DRCや製造データの再生成は行っていません。
