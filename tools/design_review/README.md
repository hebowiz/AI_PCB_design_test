# 共通レビュー用ツール

[固定保存方式](../../docs/review_artifacts.md)に従い、再利用する処理を機能別に管理する。レビュー名・ID・日付をスクリプト名に付けない。過去の専用スクリプトは今回移動せず、抽出は[移行計画](../../docs/review_artifacts_migration.md)に従う。

## 保存先の検査

```powershell
python <mainの絶対パス>/tools/design_review/check_layout.py --repo <対象Worktreeの絶対パス> --base <作業前の完全SHA>
```

Python標準ライブラリのみを使う。基準コミットから追加された追跡ファイルと、ignoreされていない未追跡ファイルを検査する。許可外の新規reportsファイル、details/batches/evidenceの新規ファイル、一時領域の追跡を検出する。終了コードは0が該当なし、1が規約違反、2が実行エラー。結果は標準出力へ出し、ファイルやCADを変更しない。

旧成果物が基準コミットに存在するだけでは違反にしない。既存ファイルの内容・検証結果・ハッシュ・技術的妥当性・スクリプトの汎用性は検査しない。manifest照合、画像確認、ERC/DRC、Git差分の確認は別途行う。未追跡でもignoreされた試行ファイルは検査対象外なので、技術的根拠を保存したかは履歴と最終成果物で確認する。

## 解析・出力処理を抽出するとき

読み取り解析は入力CAD、基準版、出力先を明示引数で受ける。CADへの書込処理は別コマンドに分け、読み取り検査から呼ばない。試行用の出力は一時領域へ向け、最終出力を固定名へ集約する。特定Worktree名やレビュー名、旧reportsの相対位置への依存を残さない。

共通ツールの変更はmainで管理する。古い設計Worktreeからもmain側ツールの絶対パスを使えるようにする。設計ブランチへ管理規則一式をマージしない。使用したツールのコミットと依存版をmanifestに記す。将来のpcb-designスキルもこの入出力契約を使用する。

## 銅箔・配線スタイルの調査

`analyze_copper_style.py --board <PCB絶対パス> --out <一時出力先> --packages <追加Python依存の場所>`をKiCad付属Pythonで実行する。KiCad 10.0.8、Shapely 2.2.0、NetworkX 3.6.1、Pillow 13.0.0で実行確認した。入力PCBを保存・再フィルせず、metrics.jsonと分析用画像を出力する。円弧配線は未対応として停止する。

検査対象は銅箔輪郭の角、中心線の途中分岐と短い45°連続曲がり、ネット別ビア、2ビアの裏面経路、保存済みGNDゾーンの形状。出力は候補一覧であり、合否や削除対象ではない。銅箔の凸角と空隙の鋭い切込みを区別する。GNDの1mm開操作には丸い角やサーマルも含まれるため、細線・半島の確定件数として扱わない。断面幅はその座標の水平/垂直値であり、全面の最小有効幅を保証しない。

ビア代替経路の直線検査は0.127mm離隔で異ネットの配線・パッド・ビアを調べるだけで、GND帰路、同一ネットパッド側面、45°での実配線、カスタムルールを保証しない。実際の撤去・修正には別途承認と検証が必要。検出候補の座標・UUID・条件はmetrics.jsonへまとめる。

画像の分析プロットとKiCadネイティブ出力を混同しない。表裏の原PDFをKiCad CLIで一時出力し、`render_review_pdf.py --front <表PDF> --back <裏PDF> --out <一時出力先> --font <フォント絶対パス>`をpypdfium2/PillowのあるPythonで実行すると、pcb_front.pngとpcb_back.pngを固定名で作成できる。裏面も上面からの投影として表示する。最終固定セットへの反映前に画像を開いて確認する。

## 検出候補の分類と画像一覧

`classify_copper_candidates.py --board <PCB> --metrics <既存metrics.json> --out <一時領域> --packages <依存ライブラリ> --assessments <分類補足JSON>`をKiCad付属Pythonで実行する。保存済み銅箔を読み、候補の断面、端子・配線・反対面参照との関係、分岐点の周囲0.01/0.05/0.10/0.25mmでの交差数を測定する。入力PCBは保存しない。最終出力は既存metrics.jsonへ集約し、検索できる画像一覧は固定名inspection.htmlに保存する。

自動分類は暫定である。`assessments`は対象PCBのSHA256、候補IDごとの分類・理由・推奨修正・追加証拠を持ち、画像と測定に基づく担当者の判断を明示して再現する。例外はユーザー承認を意味しない。断面2方向だけでは斜めのネックを否定できず、パッドの近傍だけでは正常サーマルと断定できない。判断を確定できない箇所は要修正計画へ残す。候補間の重複を除外せず、対応IDで関連付ける。

現在の補足検査はA-2のVIO閉路・重複を含む。閉路の過去版との照合には同じaudit_route_geometry.pyを用いる。分類用JSON、コンタクトシート、試行コードは一時領域へ出し、分類根拠と入力JSONはmetrics.json内に保持する。完成済みpcb-designスキルや自動合否判定として使わない。
