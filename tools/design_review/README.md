# 共通レビュー用ツール

[固定保存方式](../../docs/review_artifacts.md)に従い、再利用する処理を機能別に管理する。レビュー名・ID・日付をスクリプト名に付けない。過去の専用スクリプトは今回移動せず、抽出は[移行計画](../../docs/review_artifacts_migration.md)に従う。

## 保存先の検査

```powershell
python <mainの絶対パス>/tools/design_review/check_layout.py --repo <対象Worktreeの絶対パス> --base <作業前の完全SHA>
```

Python標準ライブラリのみを使う。基準コミットから追加された追跡ファイルと、ignoreされていない未追跡ファイルを検査する。許可外の新規reportsファイル、details/batches/evidenceの新規ファイル、一時領域の追跡を検出する。終了コードは0が該当なし、1が規約違反、2が実行エラー。結果は標準出力へ出し、ファイルやCADを変更しない。

旧成果物が基準コミットに存在するだけでは違反にしない。既存ファイルの内容・検証結果・ハッシュ・技術的妥当性・スクリプトの汎用性は検査しない。manifest照合、画像確認、ERC/DRC、Git差分の確認は別途行う。未追跡でもignoreされた試行ファイルは検査対象外なので、技術的根拠を保存したかは履歴と最終成果物で確認する。

## 解析・出力処理を抽出するとき

読み取り解析は入力CAD、基準版、出力先を明示引数で受ける。CADへの書込処理は別コマンドに分け、読み取り検査から呼ばない。試行用の出力は一時領域へ向け、最終出力を固定名へ集約する。特定Worktree名やレビュー名、旧reportsの相対位置への依存を残さない。

共通ツールの変更はmainで管理する。古い設計Worktreeからもmain側ツールの絶対パスを使えるようにする。設計ブランチへ管理規則一式をマージしない。使用したツールのコミットと依存版をmanifestに記す。将来のpcb-designスキルもこの入出力契約を使用する。
